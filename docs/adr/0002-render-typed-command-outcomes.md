# Render typed command outcomes through human and JSON adapters

Worktrees commands that support machine-readable operation return a typed command outcome before producing terminal output. The outcome separates mutually exclusive result and error values from shared repository context, effects, diagnostics, and recovery actions. Human Cliclack rendering and the versioned JSON envelope are adapters at this seam; they must not duplicate command planning or execution, and JSON must not be produced by capturing human-formatted text. Request and response JSON Schemas are derived from the same Rust types used at runtime.

This shape makes command behavior the test surface, keeps human and agent semantics aligned, and lets JSON help accurately expose inputs, outputs, errors, and next steps. The shared protocol module owns strict request parsing, version and request identity handling, byte-safe paths, response rendering, effects, diagnostics, recovery invocations, and schemas. Command modules own their typed inputs, outcomes, contexts, and stable catalogs.

JSON mode is deterministic and noninteractive: it emits one newline-terminated document on stdout, emits no ordinary stderr, and never supplies a human approval. Request mode takes all command-specific input from stdin and rejects mixed argv input. Mutating commands describe dry runs with unattempted effects. Human adapters may resolve explicit confirmation requirements before executing the same plan. Commit remains the version 1 compatibility anchor: its existing outcomes, fields, codes, and shared-generator dry-run approval behavior are retained.
